\section*{Overview}

I am a consummate, lead-by-example data engineer with decades of experience designing, implementing, deploying, retrofitting, fire-fighting, and fixing data-centric systems. Recently my focus has been on data storage and backend systems at scale, demystifying relational database issues in production systems, and providing sage advice for application and systems design.  I live in both DevOps and engineering worlds, contributing to infrastructure as code and software projects, existing and greenfield.

\section*{Employment}

\begin{itemize}

\item {\it Klar}, Senior Staff Software Engineer -- Cambridge, MA -- July 2022 - current

I administered the 30+ Postgres databases reducing incidents from weekly to none.  I redesigned all backend systems from ad-hoc code into functional dataflows orchestrated by Dagster jobs that consume Kafka events, access relational databases, communicate with 3rd party APIs, and allow for human/spreadsheet-driven business decisions when necessary.  I migrated our data warehouse from Redshift to files stored in lakeFS (Git for S3) buckets as partitioned Parquet. These are read by our OLAP workloads (DBT as well as other in-house code) via DuckDB, while streaming analytics are via ksqlDB or MaterializeDB. I reduced database infrastructure costs by two-thirds.

\item {\it BlockFi}, Senior Staff Software Engineer -- Cambridge, MA -- June 2020 - June 2022

I took ownership of the nascent observability stack and delivered (selected products, negotiated with vendors, implemented Terraform, and educated the company) a complete system for logs, metrics, tracing, and alerts.  Then I hired and mentored a team of 8 junior engineers/operators to own the systems, and promoted one to lead the team. I went on to help diagnose and fix issues in our singular instance of Postgres as our company went through explosive growth (and then contraction).

\item {\it Humio}, Principal Software Engineer -- Cambridge, MA -- September 2018 - April 2020

Humio is a log storage system similar to Splunk.  It uses Kafka in two ways, to queue and then partition the onslaught of log messages for scale-out processing and provide a CRDT-like map for cluster shared state.  I combined bloom filters and trigrams of ingested data and query terms to reduce the volume of data analyzed to its absolute minimum eliminating 99\% of I/O during query processing. This approach led to industry-leading streaming query speeds and completely eliminated the "high-cardinality" issues common in other systems.

\item {\it Onshape}, Principal Software Engineer, Architect -- Cambridge, MA -- January 2017 - October 2018

Onshape's hosted CAD system uses Git-like structure for 3D models. The storage and management of these, as well as operational data (users, accounts, etc.), were my responsibility. I owned fixing MongoDB scale-out issues while at Onshape and explored options such as Cassandra, Oracle NoSQL DB, CockroachDB (Relational), etc. as well as localized and distributed caching for this data.

\item {\it Akamai Technologies}, Senior Software Development Engineer -- Cambridge, MA -- July 2015 - December 2016

I was a member of the Labs group at Akamai where I owned the database component (design, implementation, deployment, automation, and ongoing management) for a WebRTC-based peer and multi-party video conferencing platform designed to scale out across Akamai's global network as a white-label video streaming service.  I earned the Akamai Wizards award in 2015 for designing methods to integrate DNSSEC and DANE into existing DNS systems at scale.

\item {\it Amazon AWS}, Senior Software Development Engineer -- Cambridge, MA -- July 2014 - July 2015

I wrote and deployed software for the Storage Gateway service's data and control plane as well as for the virtualized on-premise iSCSI gateway. I orchestrated the global upgrade of thousands of on-premise customer virtual machine instances.

\item {\it Basho Technologies}, Senior Software Architect -- Cambridge, MA -- Jul 2011 - Apr 2014

Basho's Riak is a distributed key/value system based on Amazon AWS Dynamo paper that formed the core concepts of S3.  At Basho, I owned the node-level data storage code which was based on early log-storage management code from Google called LevelDB.
